# i18n: localized routing

With `i18n` in nowaki.config, every locale but the default one is a URL prefix (`/ja/about`).
Routes stay locale-agnostic: the prefix is taken off before routing, so one `routes/about.tsx`
serves `/about` and `/ja/about`, and the page reads the locale.

```js
// nowaki.config.mjs
import { defineConfig } from "@nowaki-dev/runtime/config";

export default defineConfig({
  site: "https://example.com",
  i18n: { locales: ["en", "ja"], defaultLocale: "en", detect: true },
});
```

| Key | Meaning |
| --- | --- |
| `locales` | locale tags (`"en"`, `"pt-BR"`) |
| `defaultLocale` | one of `locales`, served without a prefix |
| `prefixDefaultLocale` | serve the default locale under its prefix too (`/en/about`); default `false` |
| `detect` | send a visit to `/` to the visitor's locale; default `false` |

## URLs

- `/about` is English, `/ja/about` Japanese. `/en/about` redirects (308) to `/about`.
- With `prefixDefaultLocale: true`, `/en/about` is the English page, an unprefixed page is a 404
  (API and file routes still answer), and `/` redirects (307) to `/en`.
- Middleware, layouts and the 404 page see the path without the prefix; `ctx.url` keeps the
  browser's URL.
- Server functions and live events have no locale.

## Reading the locale

```tsx
// routes/about.tsx
import { getLocale } from "@nowaki-dev/runtime/navigation";
import type { LoaderContext } from "@nowaki-dev/runtime";

const text = { en: "About us", ja: "\u79c1\u305f\u3061\u306b\u3064\u3044\u3066" } as const;

export function loader(ctx: LoaderContext) {
  return { locale: ctx.locale }; // "en" or "ja"
}

export default function About() {
  const locale = (getLocale() ?? "en") as keyof typeof text;
  return <h1>{text[locale]}</h1>;
}
```

- `ctx.locale` in loaders, actions, middleware and API routes.
- `getLocale()` (from `@nowaki-dev/runtime/navigation` or `@nowaki-dev/runtime`) in components,
  layouts and islands; in the browser it is the page's locale.
- `<html lang>` is the locale unless the page sets `lang`.

Nowaki routes locales; it doesn't translate. Keep the strings in your own module, as
`examples/gallery/lib/i18n.ts` does.

## Links

- `<Link href="/about">` keeps the current locale: on `/ja/x` it renders `/ja/about`. An href
  that already has a locale prefix keeps it.
- `<Link href="/about" locale="en">` links to the English page and sets `hreflang`;
  `locale={false}` leaves the href as written.
- `href(path, { locale })` builds the same URLs for a form `action` or `fetch`.
- `localePath(path, locale)` turns a path into another locale's path, without basePath:
  `localePath("/about", "ja")` is `/ja/about`. Use it with `ctx.redirect`:
  `ctx.redirect(localePath("/account", ctx.locale))`.
- `routePath(url)` (and `ctx.routePath`) is the path without basePath and locale, for linking to
  the current page in another locale.

A language switcher, as an island:

```tsx
// islands/LanguageSwitcher.tsx
import { getLocale, Link, type Href } from "@nowaki-dev/runtime/navigation";

const locales = [{ code: "en", label: "English" }, { code: "ja", label: "Japanese" }];

export default function LanguageSwitcher({ path }: { path: Href }) {
  const current = getLocale();
  return (
    <nav>
      {locales.map(({ code, label }) =>
        code === current ? <strong>{label}</strong> : <Link href={path} locale={code}>{label}</Link>,
      )}
    </nav>
  );
}
```

Render it from a layout with `<LanguageSwitcher path={routePath(url)} />`. Working example:
`examples/gallery/islands/LanguageSwitcher.tsx` and `examples/gallery/routes/_layout.tsx`.

## Locale detection

With `detect: true`, a GET or HEAD of the site's root (`/`, or the basePath) picks a locale and
redirects (307) to it (`/ja`); the default locale stays on `/`. The choice comes from:

1. the `nowaki_locale` cookie, when it names a configured locale,
2. else `Accept-Language` (q-values; an exact tag, then the primary subtag, so `ja-JP` finds
   `ja`).

`setLocale(locale)` sets the cookie (one year, `SameSite=Lax`). A click on a `<Link locale>`
inside an island sets it too, so a language switcher belongs in an island. Only the root is
ever redirected. Responses to `/` carry `Vary: Accept-Language, Cookie`, and the redirect is
`Cache-Control: private, no-cache`, so a cached `/` only answers visitors who stay on it.

Static output can't negotiate: the build warns and `/` serves the default locale.

## Config rules and locales

With `i18n`, `redirects`, `rewrites` and `headers` sources match the path without the locale
prefix, so a `/login` rule applies to `/login` and `/ja/login`. An internal redirect destination
keeps the request's locale (`/ja/old` → `/ja/new`). `locale: false` on a rule matches the full
path instead and leaves the destination as written.

## Content, prerendering and SEO

- Content collections: `content/blog/ja/hello.md` is the `ja` entry `hello`; `getCollection`
  returns the current locale's entries. See [Content](./content.md#localized-content).
- `staticPaths` as a function runs once per locale and receives `{ locale }`. The static adapter
  writes each locale under its prefix, with its own `404.html`.
- With a site URL, every page gets `<link rel="alternate" hreflang>` for each locale plus
  `x-default`, and the sitemap lists every locale.
