# Migrating from Next.js

This guide maps a Next.js App Router app to Nowaki. It was written from a port that exists in
this repository: the comparison blog in [benchmarks/compare](../benchmarks/compare/README.md),
which is generated in a Next.js 16 version and a Nowaki version that implement the same pages,
islands, form and API route. The snippets marked with a path come from those two apps. They are
generated by `node benchmarks/compare/gen.mjs next|nowaki --mode server` from
[lib/templates.mjs](../benchmarks/compare/lib/templates.mjs) and
[lib/features-fw.mjs](../benchmarks/compare/lib/features-fw.mjs), into
`benchmarks/compare/apps/next/` and `benchmarks/compare/apps/nowaki/`. The Nowaki twin builds,
serves, posts its form and prerenders with Nowaki 0.20.0.

Where the port doesn't cover a feature (route groups, intercepting routes, revalidation,
redirects, i18n), the Nowaki side comes from `examples/gallery` and `examples/hello` or from the
`.d.ts` files of `@nowaki-dev/runtime`.

The short version: the page tree moves from `app/` to `routes/` almost file for file, data
fetching moves from async server components into a `loader`, client components move to
`islands/` and switch from React to Preact, Server Actions become a page `action` or a
`"use server"` module, and `next.config` becomes `nowaki.config.mjs`.

## What changes in the model

- **Nothing ships to the browser unless it is an island.** In Next.js every client component
  and React itself are sent and hydrated. In Nowaki a page is server HTML, and only the
  components in `islands/` ship JavaScript. On the comparison blog at 10 posts, `/` ships
  8.79 KB of JS (gzip) in Nowaki: the islands runtime, the theme toggle and one counter.
- **Preact, not React.** Islands are Preact components. `react`, `react-dom` and
  `react/jsx-runtime` are aliased to `preact/compat`, so many React libraries work, but not all
  (see [What has no equivalent](#what-has-no-equivalent)).
- **Data comes from a `loader`.** Pages are synchronous components that receive `data`; the
  loader is server-only code that runs before the render.
- **One server.** `nowaki start` is a Rust front that serves assets and the ISR cache and runs
  rendering in a Node process. The deploy adapters (`node`, `bun`, `deno`, `cloudflare`,
  `vercel`, `static`) produce the same app for other hosts.

## 1. Set up

1. Replace Next.js and React with Nowaki and Preact:
   ```sh
   npm remove next react react-dom @types/react eslint-config-next
   npm install @nowaki-dev/runtime preact preact-render-to-string
   npm install -D nowaki
   ```
2. Copy `tsconfig.json`, `nowaki-env.d.ts` and `nowaki-jsx.d.ts` from a new app
   (`npm create nowaki@latest`), and delete `next-env.d.ts`. The compare app's `tsconfig.json`
   had `"jsx": "react-jsx"` and the `next` plugin; Nowaki's uses Preact's JSX.
3. Scripts:
   ```json
   {
     "scripts": {
       "dev": "nowaki dev",
       "build": "nowaki build",
       "start": "nowaki start",
       "prerender": "nowaki prerender"
     }
   }
   ```
4. Add explicit extensions to relative imports. Next.js resolves `"../components/Search"`;
   Nowaki's server build runs as plain ESM and needs `"../islands/Search.tsx"`.

## 2. Files

| Next.js (`app/`) | Nowaki |
|---|---|
| `app/page.tsx` | `routes/index.tsx` |
| `app/posts/page.tsx` | `routes/posts/index.tsx` |
| `app/posts/[slug]/page.tsx` | `routes/posts/[slug].tsx` |
| `app/docs/[...slug]/page.tsx` | `routes/docs/[...slug].tsx` (`params.slug` is an array) |
| `app/docs/[[...slug]]/page.tsx` | `routes/docs/index.tsx` and `routes/docs/[...slug].tsx` |
| `app/layout.tsx` | `routes/_layout.tsx` (no `<html>` / `<body>`: see [Layouts](#3-layouts)) |
| `app/posts/layout.tsx` | `routes/posts/_layout.tsx` |
| `app/(marketing)/about/page.tsx` | `routes/(marketing)/about.tsx` (same route group syntax) |
| `app/@modal/(.)photo/[id]/page.tsx` | `routes/@modal/(.)photo/[id].tsx` (same parallel and intercepting syntax) |
| `app/@modal/default.tsx` | `routes/@modal/default.tsx` |
| `app/not-found.tsx` | `routes/_404.tsx` |
| `app/global-error.tsx` | `routes/_500.tsx` (server errors) |
| `app/loading.tsx` | `routes/loading.tsx` (client navigations only, see below) |
| `app/error.tsx` | `routes/error.tsx` (client navigations only, see below) |
| `app/api/search/route.ts` | `routes/api/search.ts` |
| `app/feed.xml/route.ts` | `routes/feed.xml.ts` (a file route; the extension sets the content type) |
| `app/opengraph-image.tsx` | a file route such as `routes/og/[card].png.ts` |
| `app/sitemap.ts`, `app/robots.ts` | generated when `site` is set; or `routes/sitemap.xml.ts` |
| `middleware.ts` | `routes/_middleware.ts` (one per directory) |
| `components/*` with `"use client"` | `islands/*` |
| `components/*` (server components) | `components/*` |
| `public/` | `public/` |
| `next.config.mjs` | `nowaki.config.mjs` |
| `.env`, `.env.local` | `.env`, `.env.local` |

`loading.tsx` and `error.tsx` differ in when they show. In Next.js `loading.tsx` is a Suspense
boundary that also streams on the first load. In Nowaki both are client-router boundaries: the
loading UI shows when a client navigation takes over 150 ms, and the error UI when it fails.
On a first load, a server error renders `_500`. The error component marks the message element
`data-nowaki-error` and the retry button `data-nowaki-reset`; there is no `reset` callback to
call from server HTML.

## 3. Layouts

The root layout doesn't render `<html>` and `<body>`: Nowaki writes the document, and the
layout's attributes go in exports. CSS imports work the same way: a stylesheet imported by a
layout, a page, or a component they use is linked on the page.

```tsx
// benchmarks/compare/apps/next/app/layout.tsx
import "./globals.css";
import ThemeToggle from "../components/ThemeToggle";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <div style={{ fontFamily: "sans-serif", maxWidth: "42rem", margin: "0 auto", padding: "2rem 1rem" }}>
          <header>
            <nav><a href="/">Home</a> · <a href="/posts">Posts</a> · <a href="/stats">Stats</a> · <a href="/contact">Contact</a></nav>
            <ThemeToggle />
          </header>
          {children}
          <footer><p>Built for the framework comparison.</p></footer>
        </div>
      </body>
    </html>
  );
}
```

```tsx
// benchmarks/compare/apps/nowaki/routes/_layout.tsx
import "../styles/global.css";
import ThemeToggle from "../islands/ThemeToggle.tsx";

export default function RootLayout({ children }: { children: unknown }) {
  return (
    <div style="font-family:sans-serif;max-width:42rem;margin:0 auto;padding:2rem 1rem">
      <header>
        <nav><a href="/">Home</a> · <a href="/posts">Posts</a> · <a href="/stats">Stats</a> · <a href="/contact">Contact</a></nav>
        <ThemeToggle />
      </header>
      {children}
      <footer><p>Built for the framework comparison.</p></footer>
    </div>
  );
}
```

For `<html lang>` and other attributes, export them from the layout or a page:

```tsx
export const lang = "en";
export const htmlAttrs = { "data-theme": "light" };
export const bodyAttrs = { class: "site" };
```

Preact accepts `class`, `for` and string `style` as in HTML; `className`, `htmlFor` and style
objects work too. Nested layouts receive `children`, and a layout next to `@slot` directories
also receives `slots` (`slots.modal`) instead of Next.js's named props.

## 4. Pages and data

Next.js reads data in an async server component. Nowaki reads it in a `loader` and passes the
result to the page as `data`. The page itself is synchronous.

```tsx
// benchmarks/compare/apps/next/app/page.tsx (server mode)
import Link from "next/link";
import Island01 from "../components/Island01";
import { posts } from "../lib/posts";

export const metadata = { title: "Home — Next" };

export const dynamic = "force-dynamic";

export default function Home() {
  const latest = posts.slice(0, 10);
  return (
    <main>
      <h1>A blog</h1>
      <section>
        <Island01 start={0} />
      </section>
      <ul>
        {latest.map((p) => (
          <li key={p.slug}>
            <Link href={`/posts/${p.slug}`}>{p.title}</Link> <time>{p.date}</time>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

```tsx
// benchmarks/compare/apps/nowaki/routes/index.tsx
import Island01 from "../islands/Island01.tsx";
import { posts, type Post } from "../lib/posts.ts";

export const title = "Home — Nowaki";

export const loader = () => ({ latest: posts.slice(0, 10) });

export default function Home({ data }: { data: { latest: Post[] } }) {
  return (
    <main>
      <h1>A blog</h1>
      <section>
        <Island01 start={0} />
      </section>
      <ul>
        {data.latest.map((p) => (
          <li key={p.slug}>
            <a href={`/posts/${p.slug}`}>{p.title}</a> <time>{p.date}</time>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

`PageProps<typeof loader>` from `@nowaki-dev/runtime` infers `data` from the loader, so the
inline type above can go:

```tsx
import type { LoaderContext, PageProps } from "@nowaki-dev/runtime";
export const loader = ({ params }: LoaderContext) => ({ post: findPost(String(params.slug)) });
export default function Post({ data }: PageProps<typeof loader>) { /* ... */ }
```

| Next.js | Nowaki |
|---|---|
| `async function Page({ params })` with `await params` | `loader(ctx)` with `ctx.params` (not a promise) |
| `searchParams` prop | `ctx.url.searchParams` in the loader, or the `url` prop |
| `cookies()`, `headers()` from `next/headers` | `ctx.cookies`, `ctx.headers`, `ctx.get(name)`; `getContext()` in server functions |
| `cookies().set(...)` | `ctx.setCookie(name, value, opts)` |
| `redirect("/x")` from `next/navigation` | `return ctx.redirect("/x")` (302; pass a status for others) |
| `permanentRedirect("/x")` | `return ctx.redirect("/x", 308)` |
| `notFound()` | `ctx.status(404)` in the loader, and render the not-found UI in the page |
| `export const dynamic = "force-dynamic"` | the default: pages render per request |
| `export const dynamic = "force-static"` | `export const revalidate`, or prerender with `staticPaths` |

A post that doesn't exist: in Next.js `notFound()` renders `not-found.tsx` with status 404.
The compare twin renders "Not found" with status 200; set the status in the loader so it
matches:

```tsx
// routes/posts/[slug].tsx
export const loader = (ctx: LoaderContext) => {
  const post = posts.find((p) => p.slug === ctx.params.slug);
  if (!post) {
    ctx.status(404);
    return { post: null, html: "" };
  }
  return { post, html: marked.parse(post.body, { async: false }) as string };
};
```

A loader in a `_layout` passes `data` to that layout. Middleware can pass values to loaders in
`ctx.state`.

## 5. Static paths, ISR and revalidation

`generateStaticParams` becomes `staticPaths`. It is read by `nowaki prerender` and the static
adapter; a server build renders any param on request.

```tsx
// benchmarks/compare/apps/next/app/posts/[slug]/page.tsx (static mode)
export const dynamicParams = false;

export function generateStaticParams() {
  return posts.map((p) => ({ slug: p.slug }));
}
```

```tsx
// benchmarks/compare/apps/nowaki/routes/posts/[slug].tsx
export const staticPaths = () => posts.map((p) => ({ slug: p.slug }));
```

`revalidate` keeps its name and meaning: the page is cached for that many seconds and
re-rendered in the background when stale. Next.js needs `generateStaticParams` returning `[]`
to make a dynamic route cacheable; Nowaki doesn't.

```tsx
// Next.js (the compare app with --isr)
export const revalidate = 60;
export function generateStaticParams() {
  return [];
}

// Nowaki (the compare app with --isr)
export const revalidate = 60;
```

On `nowaki start` the ISR cache lives in the Rust front, per process, and responses carry
`x-nowaki-cache: HIT | STALE | MISS`. The cache varies by what the render read (cookies,
headers, the query); a page that reads the session or cookies is never shared.

On-demand revalidation uses the same function names. Tags are set on the page instead of on
each `fetch`:

```ts
// Next.js
const res = await fetch(url, { next: { tags: ["posts"] } });
// in a Server Action
revalidateTag("posts");
revalidatePath("/blog");

// Nowaki: routes/blog/[slug].tsx
export const revalidate = 60;
export const tags = ({ params }) => ["posts", `post:${params.slug}`];
// in an action, API route or server function
import { revalidatePath, revalidateTag } from "@nowaki-dev/runtime";
revalidateTag(`post:${ctx.params.slug}`);
revalidatePath("/blog");
```

Under `nowaki start` the purge happens before the action's response, so the redirect after it
shows fresh content. The vercel adapter purges Vercel's CDN (add `@vercel/functions` to the
app), and the cloudflare adapter purges the Worker's Cache API (with `CLOUDFLARE_ZONE_ID` and
`CLOUDFLARE_API_TOKEN` for every data center). With several `nowaki start` instances, send
`POST /__nowaki/revalidate` to each (`NOWAKI_REVALIDATE_SECRET`).

## 6. Client components → islands

A `"use client"` component becomes a file in `islands/`. Drop the directive, import hooks from
`preact/hooks`, and switch React-only props:

```tsx
// benchmarks/compare/apps/next/components/Search.tsx
"use client";

import Link from "next/link";
import { useEffect, useState } from "react";
// ...
      <input type="search" placeholder="Search titles" value={q} onChange={(e) => setQ(e.target.value)} />
      <ul className="results">
        {hits.map((h) => (
          <li key={h.slug}><Link href={`/posts/${h.slug}`}>{h.title}</Link></li>
        ))}
      </ul>
```

```tsx
// benchmarks/compare/apps/nowaki/islands/Search.tsx
import { useEffect, useState } from "preact/hooks";
// ...
      <input type="search" placeholder="Search titles" value={q} onInput={(e) => setQ((e.target as HTMLInputElement).value)} />
      <ul class="results">
        {hits.map((h) => (
          <li key={h.slug}><a href={`/posts/${h.slug}`}>{h.title}</a></li>
        ))}
      </ul>
```

- `onChange` on a text input fires on every keystroke in React. In Preact it is the DOM
  `change` event (on commit); use `onInput` for each keystroke.
- `className` → `class` (both work in Preact).
- The rest of the component (state, effects, `fetch`) is the same code.

A page or server component imports the island and renders it with props; only that island
hydrates. The props must be serializable (they are written into the HTML). Hydration can be
deferred per use:

```tsx
<SortTable rows={data.rows} />                 // hydrate on load (default)
<SortTable rows={data.rows} client:visible />  // when scrolled into view
<Chart client:idle />                          // when the browser is idle
<Map client:only />                            // no server render
```

Things a client component does with `next/navigation` hooks:

| Next.js | In an island |
|---|---|
| `usePathname()` | `location.pathname`, or `routePath(location.href)` for the path without basePath and locale |
| `useSearchParams()` | `new URL(location.href).searchParams` |
| `useParams()` | pass the params from the page as props |
| `useRouter().push(url)` | `location.assign(href(url))` (a full load; see [gaps](#what-has-no-equivalent)) |
| `useRouter().refresh()` | `location.reload()` |

Nowaki also has Jetstream islands (`export const live`), whose state stays on the server and
which ship no component JS. Next.js has no counterpart; see the Jetstream guide in
[docs/guides/](./guides/).

## 7. Server Actions → actions and server functions

A form that posts to a Server Action becomes a page `action`. It runs for every method but GET,
HEAD and OPTIONS, reads the body with `ctx.formData()` (a `FormData`, as in Next.js), and
usually redirects (Post/Redirect/Get). The form is a plain `<form method="post">`, so it works
without JavaScript.

```tsx
// benchmarks/compare/apps/next/app/contact/page.tsx
import { redirect } from "next/navigation";
import { Contact } from "../../lib/contact";

async function submit(form: FormData) {
  "use server";
  const ok = Contact.safeParse(Object.fromEntries(form)).success;
  redirect(ok ? "/contact?sent=1" : "/contact?error=1");
}

export default async function ContactPage({ searchParams }: { searchParams: Promise<Record<string, string | undefined>> }) {
  const query = await searchParams;
  return (
    <main>
      {"sent" in query && <p className="notice">Thanks, your message was sent.</p>}
      <form action={submit}>{/* fields */}</form>
    </main>
  );
}
```

```tsx
// benchmarks/compare/apps/nowaki/routes/contact.tsx
import type { LoaderContext } from "@nowaki-dev/runtime";
import { Contact } from "../lib/contact.ts";

export const loader = ({ url }: LoaderContext) => ({
  sent: url.searchParams.has("sent"),
  error: url.searchParams.has("error"),
});

export async function action(ctx: LoaderContext) {
  const form = await ctx.formData();
  const ok = Contact.safeParse(Object.fromEntries(form)).success;
  return ctx.redirect(ok ? "/contact?sent=1" : "/contact?error=1");
}

export default function ContactPage({ data }: { data: { sent: boolean; error: boolean } }) {
  return (
    <main>
      {data.sent && <p class="notice">Thanks, your message was sent.</p>}
      <form method="post">{/* fields */}</form>
    </main>
  );
}
```

Both accept urlencoded and `multipart/form-data` bodies (file inputs arrive as `File`). A
page has one `action`; a page with several forms tells them apart with a field
(`<button name="intent" value="delete">`). An action that returns data instead of a redirect
re-renders the page with it as `actionData`.

Server Actions called from client components become **server functions**: a module whose
first line is `"use server"`. The browser gets a small fetch proxy for each export. Validate
the input with `serverFn(schema, impl)` (any Standard Schema library):

```ts
// actions/todos.ts
"use server";
import { z } from "zod";
import { getContext, serverFn, ServerFnError } from "@nowaki-dev/runtime";

export const addTodo = serverFn(z.string().min(1).max(200), async (text) => {
  if (!getContext()?.cookies.user) throw new ServerFnError("Sign in first", { status: 401 });
  // ...
});
```

```tsx
// islands/AddTodo.tsx
import { addTodo } from "../actions/todos.ts";
// await addTodo(text) in an event handler
```

`"use server"` works only at the top of a module, not inside a function body. In production
an error other than `ServerFnError` reaches the client as a generic 500.

Page actions and API routes reject cross-site POST / PUT / PATCH / DELETE (403) by default,
as Next.js does for Server Actions. A webhook route opts out with `export const csrf = false`.

## 8. Route handlers → API routes

The method exports keep their names (uppercase). The handler gets `ctx` instead of a
`Request`; it can return a `Response`, a `ctx.json()` / `ctx.text()` / `ctx.html()` result, or
any value, which is sent as JSON.

```ts
// benchmarks/compare/apps/next/app/api/search/route.ts
import { posts } from "../../../lib/posts";
import { search } from "../../../lib/search";

export function GET(request: Request) {
  return Response.json(search(posts, new URL(request.url).searchParams.get("q")));
}
```

```ts
// benchmarks/compare/apps/nowaki/routes/api/search.ts
import type { LoaderContext } from "@nowaki-dev/runtime";
import { posts } from "../../lib/posts.ts";
import { search } from "../../lib/search.ts";

export const GET = (ctx: LoaderContext & { json: (v: unknown) => unknown }) =>
  ctx.json(search(posts, ctx.url.searchParams.get("q")));
```

`LoaderContext` already has `json`, so with 0.20 the type can be `ApiModule["GET"]`:

```ts
import type { ApiModule } from "@nowaki-dev/runtime";
export const GET: ApiModule["GET"] = (ctx) => ctx.json(search(posts, ctx.url.searchParams.get("q")));
```

| `Request` in Next.js | `ctx` in Nowaki |
|---|---|
| `new URL(request.url)` | `ctx.url` |
| `request.headers.get(name)` | `ctx.get(name)` |
| `await request.json()` | `await ctx.bodyJson()` |
| `await request.text()` | `await ctx.bodyText()` |
| `await request.formData()` | `await ctx.formData()` |
| `params` (second argument) | `ctx.params` |

Bodies are capped at 10 MiB by default (`NOWAKI_FORM_BODY_LIMIT`).

## 9. Middleware

Next.js has one `middleware.ts` with a `matcher`. Nowaki runs every `_middleware.ts` from the
root down to the matched route's directory, so the directory is the matcher. A route group
can hold middleware that applies only to its routes:

```ts
// examples/gallery/routes/(account)/_middleware.ts
import type { LoaderContext } from "@nowaki-dev/runtime";
import { localePath } from "@nowaki-dev/runtime/navigation";

export default async function requireUser(ctx: LoaderContext) {
  const user = await ctx.session.get<string>("user");
  if (!user) return ctx.redirect(localePath("/login", ctx.locale));
  ctx.state.user = user;
}
```

Return a response (or `ctx.redirect`) to stop the request; set headers with `ctx.setHeader`;
pass values on in `ctx.state`. Middleware runs in Node, after the config `redirects` /
`rewrites` and before the CSRF check, so don't change data in it without checking the caller.
`NextResponse.rewrite()` has no counterpart; use config `rewrites` (below).

## 10. Metadata

`metadata` and `generateMetadata` become `meta`, an object or a function of
`{ data, params, url }`. A plain `title` export works too (the compare twin uses it).

```tsx
// Next.js
export async function generateMetadata({ params }) {
  const post = await getPost((await params).slug);
  return { title: post.title, description: post.summary, openGraph: { images: [post.image] } };
}

// Nowaki
export const meta = ({ data }) => ({
  title: data.post.title,
  description: data.post.summary,
  openGraph: { image: data.post.image },
});
```

A layout's `meta` object applies to every page under it; page values win, and `openGraph` /
`twitter` merge one level deep. `canonical: true` links the page's own URL on `site`, `robots`
and `jsonLd` are supported, and with `site` set, `sitemap.xml` and `robots.txt` are generated
(`export const sitemap = false` leaves a page out). There is no `title.template`: set the full
title per page, or build it in a helper.

## 11. Links, images, fonts, scripts

**`next/link` → `<Link>` or `<a>`.** On pages with islands, Nowaki's client router handles
clicks on any same-origin `<a>` and prefetches on hover; pages without islands navigate with
full loads and ship no router. `<Link>` from `@nowaki-dev/runtime/navigation` adds the
basePath and the current locale, type-checks static paths, and takes `viewTransition`:

```tsx
import { Link, route } from "@nowaki-dev/runtime/navigation";
<Link href="/posts">All posts</Link>
<Link href={route("/posts/[slug]", { slug })}>{title}</Link>
```

The compare twin uses plain `<a>` (no basePath, no i18n). Next.js also prefetches every
`<Link>` in the viewport; Nowaki prefetches on hover or touch only.

**`next/image` → `<Image>`.**

```tsx
// Next.js
import Image from "next/image";
import hero from "./hero.jpg";
<Image src={hero} alt="" priority />

// Nowaki
import { Image } from "@nowaki-dev/runtime/image";
import hero from "./hero.jpg?image";
<Image src={hero} alt="" loading="eager" fetchpriority="high" />
```

Images are processed at build time into AVIF plus the original format at several widths, with
the file's width and height. Remote images go through the same pipeline when
`images.remotePatterns` allows them (the same key name as Next.js), fetched at build time. A
plain URL string renders a bare `<img>`. There is no request-time optimizer, no WebP output, no
`placeholder="blur"`, and no `loader` prop for an image CDN.

**`next/font` → `fonts` in nowaki.config.**

```js
// Next.js: const inter = Inter({ subsets: ["latin"], weight: ["400", "700"] });
// Nowaki
fonts: [{ family: "Inter", provider: "google", weights: [400, 700], subsets: ["latin"] }],
```

Fonts are self-hosted, with a size-adjusted fallback and a `--font-inter` variable to use in
CSS.

**`next/script` → `export const scripts`** on a page or layout: a list of module paths,
bundled and loaded as `<script type="module">`. There is no `strategy`; use an island with
`client:idle` for deferred work.

## 12. Environment variables

| Next.js | Nowaki |
|---|---|
| `NEXT_PUBLIC_API_URL` | `PUBLIC_API_URL` |
| `process.env.NEXT_PUBLIC_API_URL` in client code | `import.meta.env.PUBLIC_API_URL` |
| `process.env.SECRET` on the server | `process.env.SECRET`, or typed `env.SECRET` from `@nowaki-dev/runtime/env/server` |
| `.env`, `.env.local` | `.env`, then `.env.local` over it, then the real environment |
| `.env.development`, `.env.production` | not read |

Only `PUBLIC_*` (and `MODE`, `BASE_URL`) are inlined into client code. To validate variables
at build and start time, declare them in `env.ts` with `defineEnv({ server, public })` and a
Standard Schema per variable; importing `env/server` from an island fails the build.

## 13. `next.config` → `nowaki.config.mjs`

```js
// next.config.mjs
export default {
  basePath: "/docs",
  trailingSlash: true,
  images: { remotePatterns: [{ protocol: "https", hostname: "images.example.com" }] },
  async redirects() {
    return [{ source: "/old/:slug", destination: "/blog/:slug", permanent: true }];
  },
  async rewrites() {
    return [{ source: "/p/:slug", destination: "/blog/:slug" }];
  },
  async headers() {
    return [{ source: "/api/:path*", headers: [{ key: "cache-control", value: "no-store" }] }];
  },
};
```

```js
// nowaki.config.mjs
import { defineConfig } from "@nowaki-dev/runtime/config";

export default defineConfig({
  site: "https://example.com",
  basePath: "/docs",
  trailingSlash: "always",
  images: { remotePatterns: [{ protocol: "https", hostname: "images.example.com" }] },
  redirects: [{ source: "/old/[slug]", destination: "/blog/[slug]", permanent: true }],
  rewrites: [{ source: "/p/[slug]", destination: "/blog/[slug]" }],
  headers: [{ source: "/api/[...path]", headers: [{ key: "cache-control", value: "no-store" }] }],
});
```

- Patterns use the route syntax: `:slug` → `[slug]`, `:path*` → `[...path]`.
- `redirects` / `rewrites` / `headers` may be arrays or (async) functions, called once when
  the config is read. `headers` also accepts `{ "cache-control": "no-store" }`.
- `permanent: true` is 308, otherwise 307, or set `statusCode`.
- `trailingSlash: true` → `"always"`, `false` → `"never"`; Nowaki's default is `"ignore"`
  (both forms are served).
- The rules apply on `nowaki dev`, `nowaki start`, every adapter, and static output
  (`_redirects` / `_headers`).
- An unknown key is an error with a "did you mean" hint.

**i18n.** The App Router has no built-in i18n routing (the Pages Router's `i18n` key doesn't
apply to `app/`). Nowaki has one:

```js
i18n: { locales: ["en", "ja"], defaultLocale: "en", detect: true },
```

The default locale is served at `/`, the others under `/ja/...`; the same route files serve
every locale. `ctx.locale` / `getLocale()` give the request's locale, `<Link>` keeps it,
`<Link locale="ja">` switches it, and `detect` sends a first visit to `/` by `Accept-Language`
(or the `nowaki_locale` cookie). Config rules match the path without the locale prefix.
Next.js apps that use `app/[lang]/...` with their own middleware can move that segment out and
use this instead.

Next.js config with no Nowaki key: `output` (see below), `reactStrictMode`, `experimental`,
`webpack` / `turbopack` (Nowaki has its own bundler; build-time transforms go in `plugins`,
with Rollup-style `transform` / `resolveId` / `load` hooks), and `has` / `missing` conditions on
rules.

## 14. Build and deploy

| Next.js | Nowaki |
|---|---|
| `next build && next start` | `nowaki build && nowaki start` |
| `output: "standalone"` | `nowaki build --adapter node` → `dist/server/index.mjs` |
| `output: "export"` | `nowaki prerender` (or `nowaki build --adapter static`) → `dist/static` |
| Vercel | `nowaki build --adapter vercel` → `.vercel/output` |
| OpenNext on Cloudflare | `nowaki build --adapter cloudflare` → `dist/worker` |
| — | `--adapter bun`, `--adapter deno` |

`output: "export"` can't run Server Actions, and `nowaki prerender` can't run page actions
either. API routes (`routes/api/**`) aren't written to static output; file routes with an
extension are (`routes/search.json.ts`, with `staticPaths` when it has params), like a
`force-static` route handler. In the compare port, `nowaki prerender` wrote the 14 pages and no
`/api/search`.

`nowaki start` and the node / bun / deno adapters listen on `PORT` (default 3000). In
production, set `NOWAKI_SESSION_SECRET` if the app uses `ctx.session`, `NOWAKI_LIVE_SECRET` if
it uses live islands, and `NOWAKI_TRUST_PROXY=1` behind a reverse proxy. Per-adapter details
are in [docs/deploy/](./deploy/).

## What has no equivalent

- **React-only libraries.** Islands run on Preact. With the `preact/compat` alias, most hooks-
  based React libraries work. Libraries that depend on React internals, React 19 APIs
  (`use()`, `useActionState`, `useFormStatus`, `useOptimistic`), Server Components, or a
  React-specific renderer may not. Test each one, or pick a Preact-native alternative.
- **React Server Components.** There is no RSC payload and no async server components: data
  comes from `loader` before the render. `export const streaming = true` streams the HTML (and
  `Suspense` boundaries as they settle), and `streaming = "early"` sends the shell before the
  loaders run, but there is no per-component server streaming as in RSC, and client
  navigations fetch HTML, not a component payload.
- **Request-time image optimization.** `<Image>` works on images known at build time (local
  files and allowed remote URLs); there is no `/_next/image` endpoint for images that appear
  later (user uploads, CMS content added after the build), no WebP, no blur placeholder, and no
  custom loader.
- **A data cache.** There is no `fetch` cache, `unstable_cache` or `"use cache"`: caching is
  per page (`revalidate`) and tags are set per page (`tags`), not per request.
- **`notFound()` from a loader.** A loader sets `ctx.status(404)` and the page renders the
  not-found UI; it can't hand off to `_404.tsx`.
- **Programmatic client navigation.** There is no public `router.push()`; an island uses
  `location.assign()` (a full load), or renders a link.
- **Per-route runtime.** `export const runtime = "edge"` has no counterpart: the adapter is
  chosen for the whole app.
- **Middleware rewrites and conditional rules.** Rewrites are static config rules and internal
  only (no proxying to another origin); `has` / `missing` conditions don't exist.
- **Inline `"use server"` functions.** Server functions live in `"use server"` modules.
- **`template.tsx`, `title.template`, `draftMode()`, `after()`.**
- **`.env.development` / `.env.production`.** Only `.env` and `.env.local` are read.

## Remix

Nowaki's route modules follow Remix's: a `loader` that runs on the server before the render,
an `action` for non-GET requests, and Post/Redirect/Get.

| Remix | Nowaki |
|---|---|
| `export async function loader({ params, request })` | `export const loader = (ctx) => ...` (`ctx.params`, `ctx.url`, `ctx.headers`) |
| `export async function action({ request })` with `await request.formData()` | `export async function action(ctx)` with `await ctx.formData()` |
| `useLoaderData()` | the `data` prop (`PageProps<typeof loader>`) |
| `useActionData()` | the `actionData` prop |
| `redirect("/x")`, `json(data)` | `ctx.redirect("/x")`, `ctx.json(data)` |
| `app/routes/blog.$slug.tsx` | `routes/blog/[slug].tsx` |
| `app/root.tsx` | `routes/_layout.tsx` |
| `<Form>` | `<form method="post">` |
| `meta` export | `meta` export (an object or a function of `{ data, params, url }`) |
| resource routes | API routes and file routes |
